## 二、已知差距在哪里（105 处「待补充」逐处归因）

我把生成稿全部 105 处「待补充/待材料」逐条定位，并与原始材料、标准库做了对照核验。结论分三类：

### 2.1 ✅ 确实是「原始材料没提供」（约 60 处）—— 系统行为正确

这类**不是缺陷**：系统按「不编造、有据才补」原则诚实标注，符合 GBZ/T 196—2025 质量控制要求。

| 类别 | 处数 | 具体内容 | 为何材料里没有 |
|---|---|---|---|
| **气象细节** | 5 | 年平均最高/最低气温、年雷暴日数、往年最大积雪量、大气环境 | 可研 PDF 只给了平均气温/风速/降水/湿度；这几项需地方气象站资料 |
| **周边环境明细** | 7 | 相邻企业、居民点、学校医院敏感目标、最近距离 | 需总平面图 + 现场踏勘记录，材料未含 |

```

> 「白名单漂移 = 同型第 6 次事故」—— 导入合并时保留所有键，防止新字段被静默丢弃。

### 3.2 输入之后怎么处理

#### 3.2.1 解析与清洗（`import_materials_from_dir`, app.py:886）

```
① 遍历已上传文件, 按类别分派解析器
② 表头定位: 每类表用「关键词→列索引」定位 (不是固定列号)
   例: 定员表 _get(r, "岗位","岗位名称") / 设备表 _get(r,"设备名称","名称","设备")
③ 行级防脏:
   - 表头重复行跳过 (值==列名的行)
   - 「防护用品/个人防护」等标题行跳过
   - 多装备单元格拆分 (顿号/换行/斜杠 → 多条, 列信息整行继承)
④ 检测数据择优归并 (app.py:1420):
   - 合并键 = (因素名, 采样点) —— 只并"同因素同点"重复读, 不跨点塌缩
   - 同名冲突: 归一后名字更长者获胜
   - 分数高者胜 (_score: 有ctwa+有results+有sio2…)
   - 碎片丢弃: 名字被完整名包含且无任何数据 (如'酸酐'⊂'邻苯二甲酸酐')
   - 视觉提取行标 needs_review=True + clean_warnings
⑤ 不可信字段清洗 (table_skeleton._sanitize_untrusted):
   - 投资额无单位口径 → 置空 + 记 _untrusted_fields 标记
   - 报告引用时保持原文不推算
```

#### 3.2.2 骨架先行（`table_skeleton.build_skeletons()`）

```
36 张表一次性建骨架 (3 类来源):
  A 数据驱动表 (coverage._DATA_DRIVEN): 材料没给 → 空骨架 + status=await_data
  B 标准库驱动表 (检查表/限值表): status=await_assess, 导出时按条款现算
  C 评估链路驱动表: 传了 assess 就当场填 (fill_section 同源)
写入 project.data["built_tables"]
```

**⚠ 骨架永生机制**（本轮两次踩坑的根源）：骨架一旦写入就**只在导入时重建**，导出「骨架优先」→ 旧代码产物值会被冻结续命。故护栏必须挂**导出合并点**（见 3.5）。

#### 3.2.3 官方数据层挂接

```
knowledge/oel.py       → oel_limit (职业接触限值), hazard_factor, health_effect, occupational_disease
knowledge/gbz1_loader.py → gbz1_rule (GBZ 1—2010 设计卫生条款, 66条)
knowledge/check_result_templates.py → 检查表「检查结果/评价」列唯一产地
knowledge/standard_version.py → standard_db (标准现行/废止状态)
data/region_facts.json  → 地区气象/地质事实 (常熟市已落地, 带 file/page 溯源)
```

**铁律**：报告 = f(项目数据, 官方数据层)。LLM 只写描述性文字，数值/限值/分级一律查表。

### 3.3 每个章节怎么运用原始数据，怎么规范化生成

#### 3.3.1 章节结构（GBZ/T 196—2025 权威骨架）

```
report_struct.py:
  CHAPTERS (12章) → SUBS (二级) → SUBS3 (三级) → SUBS4 (四级固定)
                                    ↘ DATA3/DATA4 (数据驱动: 产品/工段级)
  _extract_product_units(): 从 products/设备名/工艺文本提取产品单元

    (受限空间/电离辐射/现有企业概况)
```

#### 3.3.2 正文生成（LLM 层，`web/llm_draft.py`）

```
每个单元的 prompt 组装 (build_section_prompt / build_sub_prompt / build_detail):
  ┌─────────────────────────────────────────────┐
  │ ① structure_data.get_chapter_info(sec, project, assess) │
  │    按章取项目数据子集, 格式化为 prompt 片段              │
  │    - 全量不截断 (本轮已清 materials[:80]/process_text[:1500] 等) │
  │    - field_projection 聚合器: staffing→"共31个岗位…"       │
  │ ② structure_data.chapter_must_cover(sec) → 必覆盖要素清单     │
  │ ③ structure_data._std_clauses(sec) → 标准条款 (数值以此为准)   │
  │    _score 排序: 核心词命中数×10 + 年份新 + 条款号精细 + 字母子项+50 │
  │ ④ _standard_benchmark() → 标准版本基准 (防 LLM 自补废止年份)  │
  │ ⑤ _style_spec(sec) → 本节写法 (从真稿笔法提取: 字数区间+表要求) │
  │ ⑥ _table_ref_block() → 表编号引用规则                       │
  └─────────────────────────────────────────────┘
                    ↓
              LLM 生成正文 (DashScope qwen)
                    ↓
        _fix_standard_refs(): 确定性替换废止标准号 (不靠 LLM)
                    ↓
        validate_section(): 逐节校验 (见 3.4)
```

**LLM 边界（用户铁律）**：
- 数值/限值/分级/合格判定 = **纯函数 + SQL 聚合**，LLM 不得计算
- 描述性文字 = LLM
- 引用标准必须从 `_standard_benchmark()` 逐字符照抄
- 项目没给的数据 → 标「待补充」，**不得编造**

### 3.4 事后如何进行校验

四层校验，**前两层在生成循环内同步执行，后两层在导出时/导出后**：

#### L1 逐节校验器（生成时，`web/validators.py::validate_section`）

```
每个单元 LLM 返回后立即执行 (app.py:1782):
  V-01 数值溯源: 正文数字是否都能回溯到项目数据/标准库
  V-02 幻觉检测: 报告提及的因素/物料是否在项目数据中 (materials/hazard_grid/assess)
        allowed 集 = hazards ∪ grid.factors ∪ materials(全量) ∪ 通用物理因子
        → 本轮把 mats[:60] 改为全量, 防 #61+ 材料被误报
  V-03 要素完整性: 本节必含要素 (chapter_must_cover) 是否覆盖
  V-04 重复检测: 与其他节大段重复 (V-04)
  V-05 已废止标准引用 → 报「须改引现行版本」
结果写 section_states[sec]['validation'] → 前端可见
```

#### L2 确定性标准号替换（校验前，app.py:1775）

```
_fix_standard_refs(text): 废止号 → 现行版
